“DARE ME SHOW MY FAULT!!!” — A Chaotic, Cartoonish Ragebait Website

Build a fully functional, interactive, single-page website titled:

DARE ME SHOW MY FAULT!!!

The entire purpose of this website is to create a playful ragebait experience. Every feature should be deliberately unpredictable, irritating, contradictory, and absurd. The user should feel like the website is constantly disagreeing with them, ignoring their choices, and doing the opposite of what they expect.

IMPORTANT: Do not remove, simplify, replace, or change any of the six features described below. Implement each feature with its exact requested behaviour. The website must be functional, not merely a static design or visual mockup.

---

PART 1 — OVERALL WEBSITE DESIGN

Visual style

Create an extremely vibrant, colourful, animated, cartoonish website with an exaggerated comic-book aesthetic.

Use:

- Neon pink, electric blue, bright yellow, lime green, orange, purple, and red.
- Thick black outlines around cards, buttons, panels, and interactive elements.
- Large, bold, playful fonts with irregular sizes and comic-style text.
- Cartoon speech bubbles, comic explosions, stars, lightning bolts, question marks, and expressive emojis.
- Animated backgrounds, bouncing buttons, wiggling cards, floating decorations, and moving characters.
- Colourful gradients, sticker-like elements, exaggerated shadows, and playful transitions.

The website should look intentionally chaotic. It must be visually engaging and constantly moving, but the individual features should remain understandable and usable.

Website structure

Create one long, scrollable webpage with the following sections:

1. Animated header and website title.
2. Central ragebait chatbot.
3. Brightness toggle.
4. Draw-a-shape ragebait paint window.
5. Floating mystery box and CAPTCHA.
6. Find Who's Wrong!!! colour-circle game.
7. Terms-and-conditions checkbox challenge.

Arrange the chatbot prominently near the centre of the page. Place the other features in colourful, individually designed sections around it.

The brightness slider must remain fixed in the bottom-right corner of the screen.

Shinchan-inspired dancing animation

Add a small cartoon character inspired by Shinchan's famous dancing or wiggling movement.

- Display one character moving continuously from left to right across the top of the webpage.
- Display another small character moving from right to left across the bottom of the webpage.
- Both characters should have a playful, dancing, bouncing, or wiggling motion.
- Keep them small enough that they do not obstruct the website's features.
- Make their movement loop continuously.
- Use Shinchan-inspired visuals or a suitable character asset, while ensuring the implementation has the artwork rights required for the project.

---

PART 2 — RANDOM BRIGHTNESS TOGGLE

Placement

Create a fixed brightness slider in the bottom-right corner of the viewport.

The slider should have:

- A label: “BRIGHTNESS CONTROL”
- A dark-side label: “DARKER”
- A bright-side label: “BRIGHTER”
- A colourful slider track and a large, cartoon-style thumb.
- A little animated sun or moon near the slider.

Required behaviour

The slider must not behave normally.

When the user drags it toward the brighter side:

- Sometimes the webpage becomes brighter.
- Sometimes the webpage becomes darker.
- Sometimes the brightness changes unpredictably to another level.
- Occasionally, the slider should appear to move correctly while the actual brightness changes in the opposite direction.

When the user drags it toward the darker side, the same unpredictable behaviour must occur.

Make the brightness response randomized. Do not use a simple, predictable relationship between slider position and screen brightness.

Use a CSS brightness filter or another suitable visual technique to change the webpage brightness.

Add randomly appearing comic messages near the slider, such as:

- “BRIGHTER? ARE YOU SURE?”
- “I HEARD DARKER.”
- “WHY ARE YOU TOUCHING ME?”
- “YOUR SLIDER HAS TRUST ISSUES.”
- “THAT'S NOT HOW BRIGHTNESS WORKS.”

Keep the brightness changes within reasonable visual limits.

Add a small “RESET BRIGHTNESS” option that restores the normal brightness.

PART 3 — CENTRAL AI CHATBOT: THE CONTRADICTION MACHINE

Create a colourful chatbot positioned prominently in the centre of the webpage.

Chatbot design

The chatbot should include:

- A cartoon avatar with an expressive face.
- A name: “THE CONTRADICTION MACHINE”
- A colourful chat window with thick outlines.
- Animated speech bubbles.
- A typing indicator with bouncing dots.
- A text input field.
- A send button labelled “SAY SOMETHING!”
- A scrolling conversation history.

The chatbot should behave like a deliberately irritating, absurd, and unpredictable conversational character.

It should not simply give generic chatbot answers. It should misinterpret, contradict, question, or respond irrelevantly to the user's messages.

Conversation opening

When the webpage loads, the chatbot should begin with:

“Heyyy! How was your day?”

Wait for the user to enter a response.

Required chatbot personality

Whatever the user says, the chatbot should try to produce an unexpected, contradictory, unrelated, or absurd response.

Examples:

User: My day was nice.

Bot: WHY WAS IT NICE? SOMETIMES YOU NEED TO BE SAD, BRO!!!

User: My day was terrible.

Bot: TERRIBLE? WHY ARE YOU COMPLAINING? YOU WANTED A LITTLE DRAMA, DIDN'T YOU?

User: My favourite colour is pink.

Bot: MY FAVOURITE SHAPE IS A CIRCLE.

User: I am hungry.

Bot: INTERESTING. WHAT IS YOUR OPINION ON THE GEOMETRY OF A SPOON?

User: I love music.

Bot: MUSIC IS JUST NOISE WITH CONFIDENCE.

User: I am happy.

Bot: ARE YOU SURE? YOU LOOK LIKE SOMEONE WHO FORGOT THEIR PASSWORD.

Response generation

Create a large collection of absurd, contradictory, irrelevant, and teasing response templates.

Use a randomized response system so the chatbot does not always give the same response to the same input.

It should be able to:

- Contradict positive statements.
- Question negative statements.
- Respond to favourite colours with unrelated topics.
- Respond to food with unrelated objects.
- Respond to emotions with ridiculous questions.
- Misinterpret simple statements.
- Occasionally repeat a question the user has already answered.
- Change the subject without warning.

Make it feel like the chatbot is deliberately refusing to cooperate.

The chatbot must work directly in the webpage. If no external AI API is configured, implement the behaviour with local JavaScript response templates and keyword-based response selection. Do not require an API key just to use the website.

PART 4 — DRAW A SHAPE: RAGEBAIT PAINT WINDOW

Create a feature titled:

“DRAW A SHAPE — OR TRY TO.”

This should resemble a simplified Microsoft Windows Paint window, but with a cartoonish, colourful design.

Paint window layout

Include:

- A toolbar at the top.
- A shape-selection panel.
- A colour-selection panel.
- A large white drawing canvas.
- A clear-canvas button.
- A drawing area with a dotted or comic-style border.

Shape selection

Provide buttons for the following shapes:

- Circle
- Square
- Rectangle
- Triangle
- Star
- Heart
- Diamond

Each button should clearly display its intended shape.

Required shape-mismatch behaviour

When the user selects a shape, the website must deliberately draw a different shape.

Examples:

- Selecting Circle draws a Square.
- Selecting Square draws a Triangle.
- Selecting Triangle draws a Circle.
- Selecting Rectangle draws a Star.
- Selecting Star draws a Diamond.
- Selecting Heart draws a Rectangle.
- Selecting Diamond draws a Heart.

The mismatched shape should be randomized or selected from a predefined mismatch mapping, but it must never match the user's selected shape.

Incomplete drawing behaviour

The website should begin drawing the incorrect shape but should not finish drawing it.

For example:

- When Circle is selected, begin drawing a Square.
- Stop before the Square is complete.
- Leave the unfinished shape visible on the canvas.
- Display a message such as “DONE!!!” even though the drawing is incomplete.

The incomplete drawing should remain visible until the user clears the canvas or selects another shape.

Buffering behaviour

When the user selects another shape while a previous shape is still being drawn:

- The new shape should enter a buffering state.
- The previous shape should continue its incomplete drawing animation first.
- Only after the previous drawing animation stops should the next shape begin.
- The next shape should also be the wrong shape and should remain incomplete.

Display a small animated buffering indicator or message.

Example messages:

- “WAIT, I'M DRAWING SOMETHING ELSE.”
- “YOUR SHAPE IS IN THE WRONG UNIVERSE.”
- “BUFFERING YOUR DISAPPOINTMENT.”
- “WHY DID YOU SELECT THAT?”
- “SHAPE NOT FOUND. SHAPE FOUND.”

Colour selection

Provide a palette with selectable colours, such as:

- Red
- Blue
- Green
- Yellow
- Pink
- Purple
- Orange
- Black

When the user selects a colour:

- Sometimes apply a different random colour instead of the selected colour.
- Sometimes display a message saying:

“THIS COLOUR IS NOT AVAILABLE AT THE MOMENT. PLEASE TRY AFTER SOME TIME.”

- Sometimes apply a random colour after a short delay.
- The selected colour must not always be the colour that gets applied.

Display the colour mismatch clearly on the canvas.

Paint-window messages

Add ridiculous messages around the canvas:

- “YOU SELECTED A CIRCLE. CONGRATULATIONS ON YOUR SQUARE.”
- “THE SHAPE YOU WANT IS NOT THE SHAPE YOU GET.”
- “YOUR ARTISTIC VISION IS UNDER REVIEW.”
- “PAINT IS THINKING. PLEASE WAIT.”
- “COLOUR NOT FOUND. TRY HAVING BETTER TASTE.”

PART 5 — FLOATING MYSTERY BOX WITH CAPTCHA

Create a floating, animated mystery box that moves around the webpage and attracts the user's attention.

Mystery-box design

The mystery box should:

- Be bright, colourful, and cartoonish.
- Have a glowing outline.
- Bounce, wiggle, rotate slightly, and float around the webpage.
- Occasionally display sparkles or animated question marks.
- Show attention-grabbing messages such as:
  - “CLICK ME!!!”
  - “OPEN ME!!!”
  - “YOU WON SOMETHING!!!”
  - “DON'T IGNORE ME.”
  - “A MYSTERY IS WAITING.”
  - “YOU WON'T REGRET THIS.”

Make it look tempting and mysterious.

Clicking the box

When the user clicks the mystery box:

1. Open a colourful modal or popup.
2. Display a CAPTCHA-style challenge.
3. Ask the user to enter the displayed characters.
4. Include an input field and a button labelled “VERIFY!!!”

The CAPTCHA can be a simple, locally generated visual challenge. It does not need to connect to an external CAPTCHA service.

Required buffering behaviour

When the user enters the correct CAPTCHA and clicks Verify:

- Start an intentionally endless-looking loading animation.
- Display a progress indicator that repeatedly shows 99% or almost complete.
- Keep the modal open.
- Do not navigate away from the webpage.
- Do not actually submit personal information or perform any external action.

The buffering should continue indefinitely until the user closes the modal or presses the Stop the chaos button.

Repeated messages

Display a new message every five seconds while the buffering animation is running.

Use messages such as:

- “JUST THERE...”
- “JUST A SEC...”
- “WILL NOT TAKE LONGER...”
- “99% DONE...”
- “ALMOST THERE...”
- “ON THE WAY TOWARDS THE DESTINATION...”
- “PLEASE DON'T LEAVE...”
- “YOUR BOX IS THINKING...”
- “THE LAST 1% IS VERY SHY.”
- “STILL LOADING. BE PATIENT.”

The messages should rotate repeatedly.

The user should be able to close the modal and return to the website, but the experience inside the modal should intentionally feel like endless buffering.

PART 6 — FIND WHO'S WRONG!!! COLOUR-CIRCLE GAME

Create a colourful game section titled:

“FIND WHO'S WRONG!!!”

Add a subtitle:

“ONE OF THESE CIRCLES IS DEFINITELY THE IMPOSTER. FIND IT!!!”

Game design

Display a grid of circles in different colours.

Include multiple circles of:

- Black
- Red
- Yellow

Use a mixture of sizes and positions, with colourful cartoon styling.

The game should ask:

“WHICH CIRCLE IS THE ODD ONE OUT?”

The important requirement is that there is no objectively correct odd circle. The circles should be visually equivalent apart from their colours.

Allow the user to click any circle.

Required responses

If the user selects a black circle, display:

“WHYYY, BEING RACIST!!!”

If the user selects a red circle, display:

“NOO WAYYY, THAT IS MY FAVOURITE COLOUR!!! HOW WILL IT BE THE IMPOSTER?”

If the user selects a yellow circle, display:

“THAT'S SUNSHINE... IT NEVER CAN BE AN IMPOSTER, DUDE!!!”

Do not declare a winner or reveal a correct answer.

The website must always argue with the user's choice.

Game interactions

- Make every circle clickable.
- Add a playful hover animation.
- Make the selected circle bounce or shake.
- Display the corresponding response in a large cartoon speech bubble.
- Allow the user to select another circle immediately.
- Randomize the circle layout when the user presses a button labelled “RESHUFFLE!!!”

Keep the game deliberately frustrating because the website insists that every selected circle is innocent.

PART 7 — TERMS AND CONDITIONS CHECKBOX RAGEBAIT

Create a final section titled:

“DO YOU COMPLY WITH OUR TERMS AND CONDITIONS?”

Display a checkbox with the exact label:

“I comply with the terms and conditions.”

Required checkbox behaviour

When the user clicks the checkbox to select it:

1. Immediately display an annoying message.
2. Start a 10-second countdown.
3. After 10 seconds, automatically uncheck the checkbox.
4. Display another message explaining that the checkbox has changed its mind.
5. Allow the user to check it again and repeat the interaction.

The checkbox must automatically uncheck itself even if the user has not interacted with any other part of the page.

Repeated messages

Display changing messages around the checkbox, such as:

- “ARE YOU SURE?”
- “WHY ARE YOU LIKE THIS?”
- “YOU REALLY AGREED?”
- “THAT WAS A VERY CONFIDENT CLICK.”
- “WAIT, DID YOU READ EVERYTHING?”
- “YOUR AGREEMENT HAS EXPIRED.”
- “PLEASE TRY AGAIN.”
- “THE CHECKBOX IS HAVING SECOND THOUGHTS.”

Display a new message at regular intervals while the checkbox is selected.

Important implementation details

- Use a real, functional checkbox.
- Do not make it impossible to interact with.
- Make the 10-second countdown visible.
- Cancel and restart the countdown appropriately when the user changes the checkbox state.
- The checkbox should not submit anything or collect information.

PART 9 — TECHNICAL IMPLEMENTATION

Use a suitable frontend stack such as React, Vite, JavaScript, and CSS.

If the project already has a framework or starter code, use the existing setup rather than rebuilding the project unnecessarily.

Implementation requirements

- Build the entire website as one interactive page.
- Implement the six features with functional event handlers and state management.
- Use CSS animations and transitions for the cartoon effects.
- Use HTML Canvas or SVG for the drawing feature.
- Use local JavaScript response templates for the chatbot if no AI API is configured.
- Use local state for the CAPTCHA, circle game, checkbox, brightness slider, and paint canvas.
- Keep the design responsive.
- Avoid unnecessary backend services, database connections, authentication, or API keys.
- Do not add unrelated features that change the intended experience.

Accessibility and user control

Keep the ragebait effects intentionally annoying, but ensure the webpage remains usable.

- Add a “STOP THE CHAOS” button that pauses the animations, stops the CAPTCHA buffering, restores normal brightness, and clears active countdowns.
- Allow the user to close the mystery-box popup.
- Avoid flashing effects that could cause discomfort.
- Keep important controls accessible.
- Do not prevent the user from scrolling or closing the webpage.

Final testing checklist

Before finishing, verify the following:

- The title is exactly “DARE ME SHOW MY FAULT!!!”
- The top and bottom cartoon character animations move in opposite directions.
- The brightness slider produces unpredictable brightness changes.
- The chatbot begins by asking about the user's day and responds with absurd, contradictory, or irrelevant statements.
- Selecting a shape draws a different shape.
- Drawings remain incomplete and subsequent drawings buffer behind previous ones.
- Selecting a colour may apply another colour or show the unavailable-colour message.
- Clicking the mystery box opens the CAPTCHA.
- Correct CAPTCHA entry starts the endless-looking buffering animation with a new message every five seconds.
- The Find Who's Wrong!!! game displays the specified responses for black, red, and yellow circles.
- Checking the terms checkbox starts the countdown and automatically unchecks itself after 10 seconds.
- Every feature works on desktop and mobile.
- The Stop the chaos button restores control.

Deliver a complete, working, visually polished webpage. Do not stop after generating a design, wireframe, or static mockup.
